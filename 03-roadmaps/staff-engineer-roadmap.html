Staff Engineer Roadmap

Staff Engineer Roadmap New

Jun 16, 20264 min read

Staff engineering is not “senior engineer plus three years.” It’s a different job. The work is less about how to build a thing and more about which thing to build, what it costs to operate it for five years, how to migrate off it when the cost finally bites, and how to write the trade-off down so the next staff engineer can read it instead of re-deriving it.

This roadmap is not a sequential reading list. It’s a breadth map: the published notes a staff candidate is expected to be able to reason about — not memorize, not implement from scratch, but pull the trade-offs from cold. Pick depth in 2–3 areas; have a one-paragraph mental model for the rest.

For the full chronological prep plan including non-published materials (interview drills, mock loops, behavioral STAR stories), see the private Staff Engineer Prep Plan in the vault.

The map

1. Distributed systems primitives

You need fluency, not surface knowledge.

  • Primitives — partial failure, exactly-once being a marketing term, the operational vocabulary.
  • Logical Clocks — Lamport, vector, HLC. Required to reason about causality in any system without a single source of truth.
  • Consensus — Raft / Paxos, the cost of a quorum, when you reach for it and when you don’t.
  • CAP and PACELC — the trade-off the interviewer expects you to articulate without notes.
  • Gossip — when you need O(log N) propagation without a coordinator.

2. Database internals

The question is no longer “which database” — it’s “which trade-off.”

  • Database Concepts — LSM vs B-tree, WAL, indexes, the substrate.
  • Isolation Levels — the anomalies each level quietly permits.
  • MVCC — snapshot isolation without lock storms; the technique under most modern OLTP engines.
  • Redis — the in-memory data structure server you’ll reach for in 70% of system designs.
  • DynamoDB — the canonical cloud KV story; the Dynamo paper’s commercial descendant.
  • Spanner — what TrueTime buys you and what it costs.
  • Lakehouse Architecture — the storage layer for analytics and AI.

3. Messaging and event-driven architecture

The substrate under CDC, event sourcing, and modern microservice choreography.

  • Kafka — partitioning, replication, exactly-once semantics, when it’s the answer and when it’s overkill.
  • Event Sourcing & CQRS — when the audit trail is the database.
  • CDC — getting changes out of one OLTP database into the rest of your stack without a nightly batch job.

4. APIs and the contract at the edge

  • API Design — naming, versioning, idempotency, pagination.
  • API Gateway — when the gateway earns its keep and when it doesn’t.
  • GraphQL vs gRPC vs REST — the API style trade-off, not the religious war.
  • TCP, UDP, QUIC — the transport you usually take for granted.

5. Architecture patterns

Staff-level fluency means knowing when each pattern earns its complexity tax.

  • Choreography vs Orchestration
  • Fan-Out Strategies
  • Optimistic vs Pessimistic Locking
  • Strangler Fig — the only safe way to migrate a load-bearing system.
  • Backend for Frontend
  • Multi-Tenancy — the pattern your cost-of-goods-sold lives or dies on.

6. Caching, partitioning, sharding

  • Caching Techniques — and the consistency cost of each.
  • Consistent Hashing — the partitioning primitive every NoSQL system inherits.

7. Security and identity

  • Cryptographic Primitives
  • Cryptography & Authentication
  • Authorization Concepts
  • Zanzibar — Google’s relationship-based authorization system; the reference design every modern fine-grained-permissions product cites.

8. Production and operability

  • Observability — logs, metrics, traces, and the line between monitoring and observability.
  • Testing Strategies — the test pyramid is a lie; here’s the shape that survives microservices.
  • Container & Image Internals — what you’re actually running when you run a container.

9. AI systems (the new staff vocabulary)

  • ML System Design Fundamentals — system design applied to ML.
  • RAG Architecture — the 2024–2025 canonical AI system shape.
  • Model Serving — what production inference actually costs.

Where to go next

  • The Distributed Systems Roadmap, System Design Roadmap, and AI Systems Roadmap are the depth counterparts to this breadth map.
  • The APIs & Networking and Production Systems Deep Dives series are the deep dives behind the named systems above.

The map is intentionally broader than a typical interview reading list. Staff scope is not about depth in one area — it’s about being able to navigate every area, and recognize the trade-offs from the sound of the question.
